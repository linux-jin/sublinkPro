# Smart groups

[简体中文](smart-groups.zh-CN.md)

Smart groups are **independent dynamic views**, not replacements for source groups. A node keeps its original `Group`, and the same node can match multiple smart groups. They prefer the node's stored **landing country** (`LinkCountry`, two-letter codes such as `GB,FR,DE`). If that field is empty, configured country rules infer a country from the original or display name **without changing the node or claiming the landing IP has been verified**. An already stored country always takes precedence. Matching spans source groups by default. Optionally narrow the candidates by a case-insensitive node-name keyword and one or more existing source groups.

## Use

1. In **Subscriptions → Smart Groups**, create a group, choose countries from the full searchable region catalog (including PH), optionally select a node-name keyword and source groups, and set a maximum latency, minimum speed, and freshness window (default: 72 hours). Leave source groups empty to search across all original groups; new groups default to no latency ceiling. Zero for a numeric threshold means no upper/lower threshold; zero freshness disables expiry.
2. Click **Healthy nodes** to open the candidate dialog. It shows all matching nodes, even before any test, with per-node availability or the first exclusion reason and a candidate/healthy summary. Inside the dialog choose an existing **node check profile** and click **Check candidates** to test all, or **Check node** on a single row. The whole-group action asynchronously tests *all matching* nodes (stored or name-inferred country, keyword, source groups), including failed or untested nodes; the row action tests only that candidate. A TCP profile is sufficient when minimum speed is zero; choose a mihomo download-speed profile when minimum speed is positive. The dialog listens for completed speed-test tasks to refresh; use **Refresh** if the task event was missed or the dialog was reopened.
3. A node becomes a member when its latency check succeeded with a positive delay, satisfies the optional latency ceiling, and (unless freshness is zero) has a recent latency timestamp. If minimum speed is positive, the speed check must also have succeeded, meet the minimum and have a recent timestamp. Membership is evaluated on each read. Stale or failed nodes leave the view automatically.
4. On a smart group card, click **Create subscription from group** to open a new subscription with that group preselected. Alternatively, add or edit a subscription and select smart groups directly in **Node selection**; the selector is visible even in Manual mode and automatically switches to Dynamic (or Mixed when manual nodes are already selected). You can add the same smart group to an existing subscription by editing it. The subscription list shows a separate smart-group count, not a physical source-group/node count. The subscription resolves current members when generated; its existing filtering and effective-name deduplication still apply. Direct/group/airport items precede smart-group members in the output. Preview reflects the same member criteria.

Deleting a smart group used by a subscription is rejected until it is removed from that subscription. Smart groups do not schedule their own tests: run checks manually or use the existing node-check scheduler to keep results fresh (an all-node scheduled profile also covers these countries). A manually selected check profile is used for its test settings, not its saved group/tag scope.

The member endpoint returns `candidateCount` (before health filtering), `statusCounts` (mutually exclusive reasons for candidate exclusion), all healthy member IDs, a first-100 healthy display sample (`nodes`), and paginated `candidateNodes` (query `page`, `pageSize`, default 30, maximum 100). Each candidate includes its first exclusion `reason` (empty for healthy), plus latency and speed states. The dialog paginates candidates; it does not hide untested or failed nodes. Display samples include `countrySource: "stored" | "name"`; name-inferred country is not verified landing geography. If candidates are zero, check stored `LinkCountry`, country-name rules and keyword/source-group filters; if only members are zero, the UI lists counts for failed/missing checks, threshold failures and expired/missing test timestamps. The check endpoint accepts an optional `nodeId` for one matching candidate; omitted or zero tests all. The country chooser lists regions even if no node currently has that code. Batch-filling country from names updates the node cache immediately. No physical node group is created or moved.
