# 智能分组

[English](smart-groups.md)

智能分组是**独立的动态节点集合**，不会替换原分组，也不会修改节点的 `Group`。同一节点可以同时属于多个智能分组。优先使用节点已保存的**落地国家**（`LinkCountry`）；只有字段为空时，才按现有国家规则从节点原名或显示名推断（不会写回节点，也不代表落地 IP 已核实）。已保存的国家始终优先。支持 `GB,FR,DE` 等两位国家代码，默认跨越所有原始分组；也可附加节点名称关键词和一个或多个原分组条件。

## 使用方法

1. 在**订阅 → 智能分组**创建分组，从完整的可搜索国家/地区列表（包含菲律宾 PH）选择国家，可附加节点名称关键词和原分组筛选，并设置最大延迟、最低速度和结果有效期（默认 72 小时）。原分组留空表示跨全部原分组；新建分组默认不限制最大延迟。数值阈值为 0 表示不设该上限/下限；有效期为 0 表示不检查过期。
2. 点击**可用节点**打开候选弹框；即使还没有测速，也会显示所有匹配节点及各节点的可用状态或首个排除原因。在弹框中选择**节点检测策略**，点**检测候选节点**可测全部，点击行内**测此节点**只测单个节点。批量操作异步检测满足已保存国家或名称推断国家、关键词和原分组条件的全部候选节点，包括失败或未测节点。最低速度为 0 时，TCP 延迟检测策略就可以入组；最低速度大于 0 时，需要使用 mihomo 下载测速策略。弹框会监听测速任务完成事件并尝试刷新；错过事件或重新打开时也可手动点击**刷新**。
3. 节点必须有**成功且大于零**的延迟检测结果，满足可选延迟上限，并且延迟检测时间在有效期内（有效期为 0 时不检查）。若最低速度大于 0，还要求速度检测成功、达到速度下限且速度检测时间未过期。每次查询动态计算成员，失败或过期节点会自动退出。
4. 在订阅的**动态**或**混合**模式选择智能分组。生成订阅时实时取得当前成员，然后执行原有过滤与按有效名称去重。直接节点、原分组和机场排在智能分组成员之前；预览使用相同的成员条件。

被订阅引用的智能分组不能删除，须先在订阅中移除。智能分组本身不新增定时任务：可手动检测，或使用既有节点检测定时策略持续刷新结果（全节点定时检测同样覆盖这些国家）。手动选择的检测策略只提供检测参数，不限制到策略保存的分组或标签范围。

成员接口返回 `candidateCount`（健康筛选前的候选数）、`statusCounts`（互斥的排除原因计数）、全部可用成员 ID、前 100 个可用节点样本 `nodes`，以及分页的全部候选明细 `candidateNodes`（查询参数 `page`、`pageSize`，默认每页 30、最多 100）。候选明细包含测速状态和首个排除原因，未测速/失败节点不会从弹框隐藏。展示样本中的 `countrySource` 表示已保存的国家或仅按名称推断的国家。候选数为 0 时，请检查 `LinkCountry`、名称国家规则及关键词/原分组；有候选但无成员时，页面会列出检测未成功、阈值不满足和结果时间过期/缺失的数量。测速接口可选传 `nodeId` 仅检测当前智能分组的指定候选，省略或传 0 则检测全部。国家列表不依赖于当前节点是否存在该国家；批量按名称填充国家后会立即同步节点缓存。不会实际创建或移动节点原分组。
